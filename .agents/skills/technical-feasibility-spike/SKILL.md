# Technical Feasibility Spike

Use this to test the riskiest technical assumption before buildout.

## Steps

1. Define the customer workflow being automated.
2. Identify API/provider options.
3. Estimate cost per customer and rate-limit exposure.
4. Check reliability and ToS risk.
5. Prototype only the riskiest part when needed.
6. Recommend build, buy, defer, or kill.

## Output

- Workflow being automated.
- Provider options.
- Recommended architecture.
- Cost/rate-limit assumptions.
- Reliability risks.
- Legal/ToS risks.
- Decision.
