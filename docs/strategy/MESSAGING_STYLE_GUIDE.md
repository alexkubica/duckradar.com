# MESSAGING STYLE GUIDE

Last updated: 2026 06 14

## Purpose

Use this guide for DuckRadar cold outreach, lead validation messages, follow ups, and manual sales notes.

The goal is to sound like a real operator testing relevance, not a vendor trying to force a pitch.

Use `docs/strategy/REPLY_HANDLING_KIT.md` after a prospect replies.

## Default Voice

Write like a peer.

Keep the message short, plain, and direct.

Use normal human phrasing.

Avoid polished marketing language.

Avoid sounding like an AI summary of the prospect's website.

## First Touch Rules

1. Lead with one concrete note only if it is useful.
2. Do not mirror the prospect's whole offer back to them.
3. Prefer a workflow question before a product pitch.
4. Do not over explain DuckRadar in the first message.
5. Do not include the public site link unless the prospect asks or the page helps answer the next objection.
6. Do not include price in the first message unless the test specifically needs price qualification.
7. Do not include package details such as number of actions, number of prompts, or per site mechanics in the first message.
8. Keep one low friction ask at the end.
9. If contacting through several channels, say so plainly.

## DuckRadar One Line

Default first touch description:

```text
DuckRadar turns Search Console data into a monthly client update draft, with the next SEO actions already prioritized.
```

Short variant:

```text
DuckRadar helps turn Search Console data into clearer monthly client updates.
```

Use the longer offer details only after the prospect shows interest.

## Research First Line

Default research context:

```text
I am researching how solo SEO consultants handle monthly client updates in practice.
```

Use this before pitching DuckRadar when the goal is to learn workflows and pains.

Default research question:

```text
For smaller clients, how do you currently decide what goes into the update and what gets left out?
```

This is better than asking whether DuckRadar would be useful because it asks about current behavior.

## Dashboard Line

Keep this when the buyer likely already has too many tools:

```text
The output is a client update, not another reporting tool to babysit.
```

Use this instead of saying DuckRadar is not a dashboard. It explains the benefit without sounding defensive.

## Link Policy

Do not link to `duckradar.com` in the first touch by default.

Send the link after the prospect replies with interest, asks what it is, or wants to see an example.

Reason:

The first message should validate pain and relevance. A link can make the outreach feel like a generic pitch before the conversation starts.

## Style Constraints

Avoid:

1. Repeating the prospect's full service list.
2. AI visibility hype.
3. Ranking promises.
4. Heavy product detail.
5. Fake urgency.
6. Overly neat comparison language.
7. Multiple asks.
8. Dashes in actual outreach copy.

Prefer:

1. One useful observation.
2. One simple product sentence.
3. One reason it matters.
4. One reply based question.

## Research Mode

When using research mode, prefer:

1. One useful observation.
2. One sentence of context.
3. One question about current workflow.

Avoid asking:

1. Would this be useful?
2. Would you pay for this?
3. What features would you want?
4. Do you like the idea?

## Current Research Pattern

```text
Hi Lee,

Noticed your page lists Search Console alongside Ahrefs, Screaming Frog, Sistrix and Semrush.

I am researching how solo SEO consultants handle monthly client updates in practice.

For smaller clients, how do you currently decide what goes into the update and what gets left out?
```
